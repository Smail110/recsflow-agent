# RecAgent — диалоговые рекомендации

RecAgent — прототип диалогового слоя для рекомендательной платформы. Пользователь
описывает, что хочет посмотреть или изучить, а агент уточняет условия, получает
кандидатов, проверяет ограничения и объясняет выдачу фактами из каталога.
Демо работает с локальной `qwen3:8b` через Ollama и отдельной HTTP mock-платформой.
Интеграция с Recsflow ограничена интерфейсом адаптера: внешний API для
проекта не предоставлен.

**Автор проекта — Герман Роев Александрович.** Проект выполнен индивидуально.
В работе над кодом, тестами и документацией я использовал Codex как инструмент;
в частности, с его помощью реализовал и визуально оформил интерфейс Streamlit.

Материалы работы: [отчёт в HTML](report/index.html),
[описание решения и экспериментов](report/REPORT.md),

## Что умеет прототип

- Разбирает русскоязычный запрос локальной LLM в структурированное представление
  с валидацией Pydantic. Поддержаны подбор по описанию, под настроение, похожие
  объекты и навигация по названию.
- Ведёт диалог в LangGraph: сохраняет ограничения и реакции в сессии, задаёт
  уточнения, обрабатывает новые условия и команду «ещё».
- Получает кандидатов через заменяемый provider и локальный текстовый поиск,
  объединяет списки, применяет обязательные фильтры и ранжирует допустимые
  объекты. Рабочий порядок детерминированный; обученный реранкер не подключён.
- Формирует объяснения из подтверждённых атрибутов каталога и истории.
  Настройки тона и краткости применяются к карточкам и основному ответу. При
  отказе LLM переходит в явный режим правил; отказ провайдера отражается в
  ответе и диагностике.
- Предоставляет Streamlit-чат, FastAPI `/v1/chat`, notebook, тесты, HTTP mock,
  нагрузочный runner и отдельный сценарий подключения второго mock-клиента.

Основной маршрут — `workflow-v2` с `qwen3:8b`. Названия и профили в
демонстрационном каталоге синтетические. Память сессии живёт в одном процессе;
после перезапуска диалог начинается заново.
Каталог задаёт границы подбора: например, страна производства и произвольная
тема сюжета в нём не размечены. Агент должен обозначать такие ограничения,
а не придумывать совпадение.

## Запуск

Нужны Docker, Ollama и загруженная модель `qwen3:8b`. Из корня проекта:

```powershell
ollama pull qwen3:8b
docker compose config
docker compose up --build -d
docker compose ps
```

Откройте [чат](http://127.0.0.1:8501) и начните, например, с запроса
«Хочу курс Python с практикой». Ответьте на уточнение, затем измените одно
условие или попросите ещё варианты. В том же диалоге должны сохраняться
уже принятые пожелания.

[Документация API](http://127.0.0.1:8000/docs) и
[mock-платформа](http://127.0.0.1:8090/docs) доступны отдельно.
Пример обращения к API из PowerShell:

```powershell
$body = @{user_id='demo'; message='Хочу курс Python с практикой.'} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/v1/chat -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

Проверяйте не только HTTP 200, но и подходящие карточки, режим ответа и
`telemetry.fallback_reason`. Если Ollama недоступна, агент может ответить в
`rules_fallback`; такой ответ не подтверждает работу LLM. На Windows при
ошибке Docker BuildKit из-за кириллического пути используйте вариант из
[инструкции воспроизведения](docs/REPRODUCE.md). Там же описаны установка
без Docker, тесты, notebook и запуск из отдельной чистой копии.

Порядок проверки состава исходников, отчёта и запуска из отдельной копии
описан в [контрольном списке поставки](docs/RELEASE-CHECKLIST.md).

Зависимости объявлены в [pyproject.toml](pyproject.toml), их фиксированные
версии — в [requirements-lock.txt](requirements-lock.txt). Для локальной
установки, запуска тестов и повторения метрик используйте
[REPRODUCE.md](docs/REPRODUCE.md).

При запуске через Compose запросы с неподдерживаемыми обязательными условиями
записываются в локальный журнал. В нём могут быть фрагменты сообщений;
он не предназначен для публикации. Настройки записи, просмотр журнала
и диагностика отказов описаны в [runbook](docs/runbook.md).

## Проверенные результаты и границы оценки

| Проверка | Результат | Что означает |
|---|---:|---|
| Полный диалог на DEV | 15/20 | Открытый синтетический набор; 5 диалогов не проходят критерий. |
| Полный диалог на CONTRACT | 12/12; 20/20 ходов | Все сценарии этого открытого синтетического набора прошли. |
| Неподтверждённые факты в шаблонных объяснениях CONTRACT | 0/315 | Проверены поддерживаемые шаблоны и текущий каталог. |
| LLM-симулятор и судья | 8/8 прогонов завершено, строгий успех 2/8 | Отдельный протокол с другим критерием. |
| Тесты в отдельной копии | 1170 passed, 8 skipped, 7 subtests | Пропуски требуют внешних данных или архивной записи; это проверка компонентов, а не качества свободной речи. |
| HTTP-нагрузка | По 50 запросов при concurrency 1/2/4; p95 3,96/6,77/12,76 с | Один повторяемый запрос; это не SLA для разнообразного трафика. |

DEV и CONTRACT измерены 27.09, роли LLM — 27.09, нагрузка — 27.09. Это
отдельные проверки одного прототипа. Успех диалога означает подходящую выдачу
и соблюдение условий сценария; HTTP 200 и прохождение unit-тестов его не
заменяют. Определения, даты и источники приведены в
[описании оценки](docs/EVALUATION.md).

DEV использует `data/product_llm_first_dev.json` и синтетический каталог с
seed 42; CONTRACT — `data/product_contract_ru_v1.json` и seed 137. По
MovieLens 100K калибровались распределения генератора каталога, но его объекты
и оценки не служат ответами или метками успеха. Пилот ReDial с автоматической
silver-разметкой и справочный CCPE в эти метрики не входят. Малые открытые
наборы полезны для регрессии, но не доказывают качество на реальных запросах.

Ссылки на внешние датасеты и порядок генерации собственных данных собраны в
[описании источников](docs/DATA-PROVENANCE.md). Денежная стоимость LLM
неизвестна без цены инфраструктуры. В отчёте есть отдельный условный расчёт:
при ставке 100 ₽/час за выделенную машину — 0,108/0,093/0,088 ₽ на запрос
при параллельности 1/2/4. Это анализ чувствительности, а не фактический счёт.

## Как устроен проект

```text
сообщение → структурированный разбор → проверка и память → поиск кандидатов
          → фильтры и ранжирование → уточнение или выдача → объяснение
```

| Где | За что отвечает |
|---|---|
| `app.py`, `src/recagent/api/` | Streamlit-чат и HTTP API. |
| `src/recagent/agent.py`, `workflow.py`, `state.py` | Сессия, LangGraph и переходы диалога. |
| `interpretation.py`, `request_mapping.py`, `validation.py` | Ответ LLM, схема запроса и проверка изменений. |
| `providers.py`, `recsflow.py`, `mock_platform.py` | Заменяемый provider, HTTP-адаптер и отдельный mock. |
| `retrieval.py`, `filtering.py`, `ranking.py`, `questions.py` | Поиск, жёсткие условия, порядок кандидатов и уточнение. |
| `grounding.py`, `response_generation.py` | Проверяемые факты и текст ответа. |
| `src/recagent/catalog/`, `data/` | Генератор каталога и входы оценки; сырые внешние данные не нужны для демо. |
| `evals/`, `scripts/`, `tests/` | Критерии, команды измерения и автоматические проверки. |
| `configs/`, `notebooks/`, `report/` | Настройки, исполняемый пример и материалы отчёта. |

Подробная карта модулей и поток данных — в [архитектуре](docs/ARCHITECTURE.md).
Для другого домена есть [пример подключения клиента](docs/CLIENT-ONBOARDING.md);
внешний Recsflow требует [подтверждения контракта](docs/contract/INTEGRATION-CHECKLIST.md).

## Ограничения и дальнейшая работа

На DEV остаются ошибки понимания уровня курса и разрешения противоречивых
пожеланий. Для их дальнейшего исправления нужны разнообразные русские запросы
с проверенной разметкой. Получить такую оценку оказалось сложнее, чем собрать
демонстрационный каталог: готовые внешние источники не дают всех нужных
диалоговых меток. Поэтому я отдельно указываю малый размер выборки и продолжаю
рассматривать качество понимания запросов как основное направление развития.

Экспериментальная NLI-проверка изучалась как способ подтверждать извлечённые
условия по словам пользователя. В основной маршрут она не включена:
достаточная надёжность на разных формулировках пока не подтверждена.
Подробные следующие шаги и условия приёмки — в
[плане развития](docs/DEVELOPMENT-ROADMAP.md). Production-готовность и качество
на реальном трафике пока не заявляются.
