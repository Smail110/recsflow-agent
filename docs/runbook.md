# Запуск и диагностика RecAgent

Этот runbook относится к локальному демо: Streamlit, FastAPI, отдельный HTTP
mock и Ollama на хосте. Порядок чистой установки и проверки результатов — в
[REPRODUCE.md](REPRODUCE.md). Внешний production Recsflow здесь не подключён.

## Проверка сервисов

```powershell
docker compose config
docker compose up --build -d
docker compose ps
Invoke-RestMethod http://127.0.0.1:8090/health
Invoke-RestMethod http://127.0.0.1:8090/ready
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/ready
Invoke-WebRequest http://127.0.0.1:8501/_stcore/health
```

Чат: `http://127.0.0.1:8501`. OpenAPI API: `http://127.0.0.1:8000/docs`.
Если readiness не проходит, смотрите журналы соответствующего контейнера:

```powershell
docker compose logs --tail 100 api platform demo
```

`/health` отвечает за живость процесса, `/ready` — за готовность зависимостей.
Успешный health сам по себе не означает полезную рекомендацию. Для проверки
отправьте `/v1/chat` и проверьте карточки, ограничения, режим и telemetry,
как показано в [инструкции](REPRODUCE.md).

## Ollama и ограниченный режим

По умолчанию используется `qwen3:8b`. Проверьте `ollama list` и доступность
Ollama для контейнера через `host.docker.internal:11434`. В чате режим можно
выбрать в боковой панели. При отказе LLM агент может ответить в режиме
`rules_fallback` с уровнем `NO_LLM`: это честная деградация, но не подтверждение
работы модели. В `telemetry` смотрите `request_id`, `mode`, `provider`,
`success`, `llm_calls`, `tokens`, `fallback_reason` и `latency_ms`.

| Уровень | Что получает пользователь |
|---|---|
| `FULL` | Работающий выбранный маршрут, проверенные ограничения и объяснения. |
| `NO_LLM` | Ограниченный разбор по правилам при недоступной модели или исчерпанном бюджете. |
| `NO_EXPLAIN` | Только ID платформы при отсутствии проверенных метаданных; это не полноценные карточки, прошедшие фильтры. |
| `UNAVAILABLE` | Ошибка доступности рекомендаций, без вымышленных объектов. |

Число вызовов и токенов записывается по запросу и суммарно. Неизвестные
показатели остаются `null`/`unknown`; их нельзя интерпретировать как нулевой
расход. Перед изменением таймаутов или числа повторов измерьте фактическую
причину задержки и проверьте качество после изменения.

## Диалог и повторный запрос

Сессия хранится в памяти процесса. TTL по умолчанию — 3600 секунд бездействия;
перезапуск также очищает сессии. Если после паузы API сообщает, что сессия
истекла, начните новый диалог в UI или отправьте запрос без `session_id`.
Условия, ожидающие уточнения, показаны отдельно от принятых и не должны
незаметно менять поиск.

Идемпотентный повтор с тем же ключом и тем же сообщением внутри окна возвращает
сохранённый бизнес-ответ без нового вызова LLM или provider. В telemetry у
такого ответа `cache_hit=true`, `llm_calls=0`, `tokens=0` для **повтора**, а
`original_request_id` указывает исходный запрос. Это не означает, что исходная
обработка была бесплатной. Иной payload с тем же ключом даёт конфликт.

## Тон и длина ответа

Поля `explanation_tone` и `explanation_length` передаются в каждом запросе
`/v1/chat`. Без них действует обычный нейтральный ответ (`neutral`, `normal`).
Для дружелюбного короткого сообщения отправьте:

```powershell
$chatBody = @{
    user_id = "style-demo"
    message = "Подберите фильм: жанр комедия, тон лёгкий."
    explanation_tone = "friendly"
    explanation_length = "short"
} | ConvertTo-Json
$chatBytes = [System.Text.Encoding]::UTF8.GetBytes($chatBody)
$chatResponse = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/v1/chat" -ContentType "application/json; charset=utf-8" -Body $chatBytes
$chatResponse.message
$chatResponse.recommendations
```

Передача UTF-8 в виде байтов сохраняет кириллицу в Windows PowerShell.
Если ответ перешёл в состояние `recommend`, его основной текст содержит
не более двух объектов и одного проверенного факта на каждый. Дружелюбный
тон меняет только вступления. Полный список карточек остаётся в
`recommendations`; сокращение сообщения не меняет подбор или порядок.
Объяснения карточек также учитывают эти поля по своей прежней логике.

Те же настройки действуют при сборке ответа без генератора LLM, в том числе
после его отказа. Уточнения и ошибки не переформулируются. Для возврата к
обычному оформлению передайте `neutral` и `normal` или уберите оба поля.
Произвольные инструкции о стиле бренда этот интерфейс не принимает.

## Диагностика качества

Если HTTP вернул 200, а подбор не подходит, проверьте последовательно:

1. Что агент извлёк из реплики и какие условия принял или оставил ожидающими.
2. Были ли кандидаты у provider и BM25, найдены ли их метаданные.
3. Какие объекты исключил обязательный фильтр и почему.
4. Был ли вопрос конкретным и нужен ли он для выдачи.
5. Подтверждается ли каждое утверждение объяснения атрибутом каталога или
   известной историей пользователя.

Исправлять следует общий механизм с парным сравнением на неизменных входах.
Текущие значения и ограничения метрик — в [EVALUATION.md](EVALUATION.md).
Для эксперимента сохраняйте входы, model digest, настройки, сырые ответы,
ошибки, задержку и решение о принятии либо отклонении изменения.

## Журнал пожеланий, которых нет в каталоге

При запуске через Compose демо и API записывают непроверяемые обязательные
пожелания в `runtime/catalog-gaps/demo.jsonl` и
`runtime/catalog-gaps/api.jsonl`. Это помогает понять, каких атрибутов
не хватает каталогу. Обычная пустая выдача и приблизительные предпочтения
в этот журнал не попадают.

Запись содержит время, режим, состояние ответа, причину и цитату из пожелания
длиной до 160 символов. Полное сообщение, user ID и session ID отдельными
полями не сохраняются, но цитата может совпасть с коротким сообщением целиком.
Email, ссылки и похожие на телефонные номера строки маскируются; это не
гарантирует удаления всех персональных сведений.

Посмотреть сводку:

```powershell
.venv\Scripts\python.exe -m scripts.summarize_catalog_gaps
```

Частота означает число ходов с одинаковой фразой, а не число людей.
Близкие формулировки нужно группировать вручную. `field_hint` служит
подсказкой разбора и не подтверждает наличие признака в каталоге.
Повтор HTTP-запроса с прежним `message_id` не добавляет событие, пока ответ
есть в кэше процесса.

Без Compose запись по умолчанию выключена. Чтобы включить её, задайте
`RECAGENT_CATALOG_GAP_LOG_PATH` с локальным путём до запуска приложения.
Используйте отдельный путь для тестовых прогонов. Журналы исключены из Git;
перед показом другим людям сообщите о записи фрагментов запросов и определите
срок их хранения.

## Настройки и остановка

Рабочие настройки читаются из `configs/workflow-v2.yaml` и поддерживаемых
переменных окружения в `src/recagent/config/settings.py`. Compose явно
подключает mock-платформу. Для реального provider требуется сверить контракт,
авторизацию и capabilities по [интеграционной инструкции](contract/INTEGRATION-CHECKLIST.md).
Остановить локальные сервисы:

```powershell
docker compose down
```

Остановка и перезапуск удаляют только состояние сессий в памяти; исходники и
файлы оценки этой командой не изменяются.
