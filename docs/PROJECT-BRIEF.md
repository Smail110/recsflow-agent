# Исходное задание: краткая сверка требований

Это структурированная выжимка из текста задания, предоставленного автором проекта.
Она нужна для проверки состава поставки; подробные критерии и формулировки остаются
в исходном задании. Проект выполнил Герман Роев Александрович.

## Цель

Создать демонстрируемый диалоговый рекомендательный агент поверх API Recsflow:
понимать естественный запрос, получать кандидатов через инструменты, уточнять
недостающие условия, выдавать рекомендации с проверяемыми объяснениями и измерять
качество диалога. Реальный контракт внешнего API в задании не приведён.

## Функции

1. Локальная open-source LLM со structured output и валидацией Pydantic. Типы
   запросов: подбор по описанию, «похожее на», рекомендация под ситуацию или
   настроение, навигация по каталогу. Обработка неполных и противоречивых условий.
2. Слой инструментов: candidate retrieval, item metadata lookup, фильтры
   каталога, реранжирование и уточняющий вопрос. Оркестрация через LangGraph;
   политика уточнений должна учитывать ожидаемую пользу для качества выдачи.
3. Объяснение по фактам каталога и связи с запросом или историей пользователя;
   автоматическая отбраковка неподтверждённых утверждений. Настраиваемые тон и
   длина под бренд клиента.
4. Диалоговые состояния «разбор → retrieval → уточнение → выдача → обратная
   связь», память условий и реакций, бюджет LLM-вызовов, деградация при сбоях.
5. Офлайн-симулятор пользователя и LLM-судья. Метрики: успешность диалога,
   среднее число уточнений, доля галлюцинаций, латентность.
6. Чат-демо и REST-эндпоинт; нагрузочное тестирование, задержка и стоимость
   LLM-вызовов; анализ узких мест и план продуктивизации.

## Формат сдачи

- Git-репозиторий с исходниками, README, зависимостями, unit-тестами, notebook
  и нужными конфигурациями. По README проверяющий должен развернуть решение и
  повторить ключевые результаты.
- Самостоятельный итоговый PDF или HTML: постановка, решение, эксперименты,
  метрики, выводы. Допускается файл в `report/` или отдельное вложение.
- Для веб-сервисов: Dockerfile, инструкция запуска и скринкаст 2–5 минут.
- Внешние датасеты передаются ссылками. Синтетические данные должны создаваться
  воспроизводимым скриптом с фиксированным seed.
