# Что выполнено по заданию

Я реализовал прототип диалогового слоя над рекомендательной платформой.
Ниже сопоставлены требования [исходного задания](PROJECT-BRIEF.md) и
полученный результат. Архитектура, эксперименты и выводы подробно описаны
в [отчёте](../report/REPORT.md).

| Требование | Что есть в проекте | Граница результата |
|---|---|---|
| Исследовательская основа | [Обзор CRS, ReAct, RRF, RAG и LLM-as-a-Judge](RESEARCH-BASIS.md) с первичными источниками. | Используются отдельные принципы; результаты статей не приписываются прототипу. |
| Локальная LLM и структурированный запрос | `qwen3:8b`, Ollama, Pydantic; подбор по описанию и настроению, похожие объекты, поиск названия. | Не каждое выраженное естественным языком пожелание разбирается правильно. |
| Инструменты агента | Получение кандидатов и метаданных через provider, BM25, объединение результатов RRF, фильтры, ранжирование и уточнение. | Ранжирование детерминированное; обученный реранкер не используется. |
| Диалоговый оркестратор | LangGraph, память условий и реакций, бюджеты LLM, исправление условий и команда «ещё». | Память находится в одном процессе; перезапуск очищает сессии. |
| Объяснения | Проверка фактов шаблонов по каталогу и истории, управление тоном и длиной. В CONTRACT 27.09 — 0/315 неподтверждённых фактов. | Это проверка поддерживаемых шаблонов, а не любых утверждений свободного текста. Тон и краткость работают в основном ответе и при fallback; произвольный брендовый голос не обучался. |
| Офлайн-оценка | DEV: 15/20 диалогов; CONTRACT: 12/12 диалогов, 20/20 ходов на 27.09. Отдельные LLM-симулятор и судья. | В DEV остаются пять неуспехов. Малые открытые наборы не оценивают качество на реальном трафике. |
| Симуляция диалогов | Протокол 27.09 завершился в 8/8 случаях; строгий успех — 2/8, в среднем 0,75 уточнения. | Завершение вызовов ролей не означает успешную рекомендацию. Это отдельный набор и критерий. |
| Демо и API | Streamlit, FastAPI `/v1/chat`, notebook, отдельный HTTP mock, второй mock-клиент, telemetry по запросу. | HTTP 200 не подтверждает полезность ответа. Реальный API Recsflow не предоставлен. |
| Нагрузка | 27.09 выполнено по 50 запросов при concurrency 1/2/4; p95 — 3,96/6,77/12,76 с. | Один повторяемый запрос, без production SLA. Фактическая стоимость неизвестна; отдельно дан сценарный расчёт по условным ставкам 50/100/200 ₽/час. |
| Материалы сдачи | README, инструкции, конфигурации, Dockerfile, тесты, notebook, HTML-отчёт и видео. | Запуск проверяется на точном составе поставки; порядок — в контрольном списке. |

Наличие файла в этом списке само по себе не подтверждает успешный запуск.
Состав и воспроизводимость проверяются по [контрольному списку](RELEASE-CHECKLIST.md).

Определения метрик, даты и ограничения приведены в [EVALUATION.md](EVALUATION.md),
происхождение данных — в [DATA-PROVENANCE.md](DATA-PROVENANCE.md), порядок
проверки поставки — в [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md).

NLI-проверка извлечённых условий остаётся исследовательским компонентом.
Она выключена в основном маршруте: проверенные варианты не обеспечили
достаточной надёжности на разных формулировках.

Для настоящей интеграции с Recsflow нужны endpoint, credentials,
подтверждённая схема и staging с тестовым каталогом. Предложенный OpenAPI
описывает границу локального адаптера. Для внешних пользователей дополнительно
понадобятся авторизация, постоянное хранилище сессий, мониторинг и согласованные
показатели доступности и задержки. Эти задачи перечислены в
[плане развития](DEVELOPMENT-ROADMAP.md). Production-готовность не заявляется.
