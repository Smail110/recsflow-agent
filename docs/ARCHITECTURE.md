# Устройство RecAgent

Основной маршрут приложения — `workflow-v2`: локальная LLM предлагает структурированное
понимание запроса, а код проверяет его, хранит состояние и отвечает только по
известным объектам каталога. Streamlit и FastAPI собирают агента через общую
фабрику. Provider можно заменить без переписывания диалога; пример Recsflow
в этом проекте работает с предложенным mock-контрактом, поскольку внешний
production API не предоставлен. `baseline-v1` сохранён отдельно для сравнения.

## Путь одного сообщения

```text
Streamlit / HTTP API
       ↓
сессия и бюджет → Ollama structured output → проверка по схеме и фразе
       ↓                                  ↓
принятые условия и реакции          ожидающее уточнение
       ↓
provider retrieval + локальный BM25 → RRF → обязательные фильтры
       ↓
уточняющий вопрос или ранжирование → проверенные факты → ответ и telemetry
```

Запрос получает `request_id`; ответ содержит режим, источник кандидатов,
число LLM-вызовов, учтённые токены, задержку и причину fallback. Общие
счётчики сохранены отдельно от telemetry конкретного запроса. Если метаданные
не позволяют проверить обязательное условие, агент не выдаёт объект как
подтверждённо подходящий. Если LLM недоступна, срабатывает явный ограниченный
разбор по правилам. Сессии и записи повторных запросов находятся в памяти
процесса; постоянного хранилища пока нет.

## Границы компонентов

### Оформление ответа

В `ChatRequest` доступны `explanation_tone` (`neutral` или `friendly`) и
`explanation_length` (`normal` или `short`). По умолчанию используются
`neutral` и `normal`: обычный текст ответа остаётся прежним.

Настройки работают и для объяснений в карточках, и для основного сообщения
с рекомендациями. В режиме `short` сообщение содержит не более двух объектов
и одного проверенного факта на каждый. Режим `friendly` меняет вступления
на «Предлагаю посмотреть…» и «Ещё один вариант…». Состав и порядок карточек
от этого не меняются; их собственное оформление сохраняет прежнюю логику.
Короткий ответ не означает, что остальные рекомендации исключены из выдачи.

Стиль применяется после выбора проверенных фактов. Он не меняет условия
поиска, ранжирование, prompt модели или разрешённые утверждения. При отказе
генератора либо исчерпании бюджета LLM прямой ответ из фактов каталога
использует те же настройки. Уточняющие вопросы и сообщения об ошибках
сохраняют исходный текст.

Встроенные генераторы поддерживают отдельную копию настроек на запрос через
`with_style`; интерфейс `generate` не изменён. Сторонний генератор без этой
возможности продолжает работать со своим оформлением. Это два фиксированных
тона и две длины ответа, а не произвольный профиль стиля бренда.

### Каталог и эксплуатация

Внешний provider обязан возвращать кандидатов и проверяемые метаданные;
поддержку истории и точного поиска названия он объявляет явно. Один только
ID или score не подтверждает длительность, жанр и другие атрибуты. Для
`navigation` и `similar` нужен подтверждённый поиск по названию — у mock
он есть, у реального Recsflow это неизвестно. Предложенный OpenAPI расположен
в `docs/contract/openapi.yaml`; порядок сверки настоящей платформы — в
[INTEGRATION-CHECKLIST.md](contract/INTEGRATION-CHECKLIST.md).

Бюджеты вызовов LLM и вопросов ограничивают сессию, но не превращают
синхронный граф в распределённый сервис. Подключение Redis, авторизации,
квот, мониторинга и эксплуатационных SLO относится к следующему этапу
после подтверждения требований среды. План — в
[DEVELOPMENT-ROADMAP.md](DEVELOPMENT-ROADMAP.md).
